# Copilot Usage Monitor (Local)

A free, open-source VS Code extension that shows **your own GitHub Copilot CLI, Claude Code and Codex CLI usage, in tokens (and Copilot's estimated USD), as observed in their session logs on this computer**. It puts a status-bar item, a side bar summary and a details panel in VS Code. It reads no credentials, stores nothing and has no runtime dependencies. It makes no network calls, unless you choose a display currency other than USD (see [Currency](#currency)).

Not affiliated with, endorsed by or supported by GitHub, Microsoft, Anthropic or OpenAI.

Every figure carries its **source**: Copilot, Claude Code or Codex. Projects are grouped by folder name across all three, so a repository you work on with more than one tool is one row. Claude Code and Codex log no cost, so their figures are tokens only; estimated USD covers Copilot alone.

## What it shows

- **Status bar:** `Local today: 1.5M tok`. That is input plus output tokens for today, from local midnight. In USD view it shows this month's estimate instead, for example `Local Nov: $12.40 / $20.00–$60.00`. The month figure is never filtered. Set `copilotUsageMonitor.statusBar` to `month` or `session` to show this month or the current session instead, in either unit; the icon always shows this month's target state. The tooltip keeps every figure, says when a figure includes session totals, and gives the current session's last prompt (its own call plus the agent calls it triggered). When more than one source has records today, it adds one line per source under **By source today**. With no logs from any enabled source it reads `Local: no usage logs found`. With more than one source enabled, screen readers hear "Local usage, today: …". Click it to open the panel.
- **Side bar** (the extension's logo in the activity bar, "Copilot Usage (Local)" → **Summary**): a compact summary in small groups, label on the left and figure on the right, in the Tokens / USD (est.) unit. Nothing in it is filtered except the Insights count, which follows the panel's filter.
  - **This workspace · *folder***: Today and Last 7 days for the project that matches an open workspace folder (by folder name). Hidden when nothing matches.
  - **All projects**: Today, Last 7 days and This month, with a small marker for your target state (under, in range or over).
  - **By source, last 7 days**: one row per enabled source whose folder was found (`—` when it has no record), shown when Claude Code or Codex is on and found. Click a row to filter the panel to that source and open Overview (click again to clear).
  - **Top projects, last 7 days** (5) and **Top models, last 7 days** (5). Click a project to filter the panel to it and open Projects (click again to clear); click a model to open Models.
  - **Insights**: "N findings · Review" when the panel's month has any. A data-health note appears only when data is partial or the log format changed. A small "Copilot Chat in VS Code not counted" line, always there, opens Data health.
  - **Open dashboard** opens the details panel; the link under it switches the unit. The **Currency: USD** footer link (it shows the chosen code) opens the currency picker, also in the side bar's `…` menu as **Choose Currency…**. Hover a row for its calls, session totals and other details. Title buttons: Open panel, Switch unit, Refresh.
  - While loading ("Reading session logs…"), or when no logs are found or a folder cannot be read, the view says so and names the folder setting of each enabled source (`copilotUsageMonitor.copilotHome`, `claudeHome`, `codexHome`). While the history is first read it says "Reading history (n of N files)…".
- **Details panel** ("Copilot Usage (Local)"): a left-hand section menu (a wrapping row of links when the panel is narrow), with the month picker, the Tokens / USD (est.) switch and any filter chips (project, tool or source, for example "Source: Claude Code") at the top of every section. The Models, Projects, Sessions and Tools tables mark each row with a small source chip. Pick a section by clicking it, from a side bar row, or with **Copilot Usage: Show Section…**. Month, unit and filter changes keep the section you are on.
  - **Overview:** opens with the **Today** hero figure (with yesterday, the 7-day average and the change against yesterday) beside a daily-activity heatmap (one square per day, the last 20 weeks) and a cache ring (the viewed month's cache-read share of input). A **By source** card lists the viewed month per source (tokens or USD, calls, sessions; USD shows `—` for Claude Code and Codex); click a row to filter to that source. Then tiles for the current session, the last 7 days (with the change against the 7 days before, as ▲ or ▼; no arrow when either week has nothing logged, and no comparison when the 7 days before reach back past the first month read) and the viewed month (with your target range, if set, and the change against the same point last month as an amount, for example `▲ $2.70 Nov 1–6 vs Oct 1–6 ($6.40)`; a past month compares with the whole month before). Then the **last 30 days** as bars (a dashed average line, today highlighted), and the **monthly trend**: one bar per month; click a bar to open that month.
  - **Daily:** today in detail (input, output, cache read, cache write, reasoning, model time, AIU (as logged), USD (est.) and calls), the **daily trend** (one bar per day of the viewed month, a dashed line at the average per active day and the peak day highlighted) and a month calendar of daily tokens or USD. Session totals count on the day the session ended.
  - **Sessions:** the current session, then the viewed month's sessions, largest first: the top 10, with the rest folded under "Show N more". A ▲ marks sessions whose last 5 calls cost 3× or more than their first 5, which means the context kept growing and a fresh session would likely be cheaper. Rows counted from a session total carry a "session total" tag. A Claude Code or Codex session has no lock file, so it counts as live while one of its logs changed in the last 5 minutes (today), and reads "idle", never "ended", otherwise. Click a session to list its calls at the top of the section: time, model, who started it (you or the agent), uncached input, cache read, cache write, output, reasoning, the share of input taken by tool definitions, AIU, USD (est.) and how the call ended (an answer or tool calls). The newest 200 calls of a session are kept; older ones are counted but not listed. A **Prompts and agent calls** card says how many agent calls your prompts triggered in the viewed month and what a prompt cost on average (a prompt plus the agent calls after it, up to your next prompt).
  - **Models:** the viewed month's per-model table, with each model's share, estimated USD and USD per call (from per-call records only). **Cache by model** shows the cache-read share of input, and the exact estimated cost of the uncached input next to what the same tokens would cost at the cache-read price, from the per-token-type AI credits Copilot logs with each call (`—` where none were logged).
  - **Change vs last month:** the Projects, Models and Tools tables add a **Δ vs Oct 1–6** column: this month so far minus the same point last month (a past month: minus the whole month before), in the active unit and currency, under the same filters as the table. It is ▲ or ▼ with the amount, never a percentage; "new" when nothing was logged then, and no arrow when either side has nothing logged. With `historyMonths` at 1 (or the month before outside the window) there is no column, and the table says why.
  - **Projects:** usage per folder name, across sources (a worktree under `.claude/worktrees/<name>` or `.worktrees/<name>` counts under its repository's folder). Copilot's `owner/repo` is shown as the row's label, the same way session titles are: the most recently active Copilot session that reported one wins, so two sessions in one folder that disagree show the newer value. Two different repositories cloned into folders of the same name share one row. Click a row to filter the month view, trend and tables to that project; click the chip's ✕ to clear.
  - **Tools:** each tool the model used, built-in or added by MCP servers, plugins and extensions (added tools summarised per server or plugin), judged by each source's own built-in tools. Claude Code's tools come from the names of its `tool_use` blocks; Codex tools are not counted. Click a row to filter by that tool. Session totals have no tool data, so a tool filter leaves them out. **Tool definitions in the prompt** shows how much of the input the tool descriptions took, overall and for the calls that used each server or plugin. It is a share of input, already in every total, not an extra cost.
  - **Insights:** calls past a model's long-context price threshold, sessions that grew costly and models with low cache reuse in the viewed month. Built from per-call records only; session totals are left out. Insights use Copilot's logged AI credits, so Claude Code and Codex calls are not examined (the section says so when they are in scope).
  - **Data health:** what was read, what was skipped (including sessions counted from session totals) and what is not counted. It opens with the provenance note (what the figures are and are not), then "Not covered: Copilot Chat in VS Code (only Copilot CLI logs are read), so figures are a lower bound for Chat users." A **Sources** box has one row per source: "Off" with the setting that turns it on (`copilotUsageMonitor.claudeCode` or `.codex`), folder not found, unreadable, or "N files, M sessions read", then that source's own counters (unreadable logs, lines in an unknown format, malformed lines, over-long lines, files beyond the 10,000-file scan cap, which also mark the data partial, Codex archived sessions not read). A Claude Code or Codex session whose logs hold only your prompts (no model call yet) is not counted as a session without usage data.
  - **Month picker:** step back through up to 24 months of history (12 by default) with ‹ ›, or pick one from a list. Today and the current session stay live while you look at an old month.
  - **Personal target range** (optional): say how much you mean to use per month, for example $20–$60. The status bar icon shows whether this month is under (↓), in (✓) or over (🔥, amber) the range. It never stops Copilot, and it never pops up unless you opt in: with `copilotUsageMonitor.targetAlert` on (off by default), one notification says when this month's estimated cost first goes above your target max, at most once per calendar month per VS Code window, with **Open dashboard** and **Don't show again** (which turns the setting off). Nothing is stored to remember it; a new window may say it again. It needs a target max, and with a non-USD currency it waits for the exchange rate.
  - Today, the current session, the last 7 days and the status bar are never filtered. Long tables show their top 10 rows and fold the rest; an active filter row always stays visible.
  - **Colours:** the **Colours…** button next to the unit switch (also **Copilot Usage: Choose Colours…**, and in the side bar's `…` menu) picks a premade palette for the panel: **Theme** (your colour theme's chart colours, the default), **Ember** (orange), **Ocean** (blue), **Forest** (green), **Violet**, **Rose** or **Graphite** (slate grey). A palette sets the accent (today, the active section, the heatmap, the cache ring) and the four model-family colours, with its own shades for light and dark themes; the family colours in every palette stay apart under red-green colour-blindness simulation and read as text. High-contrast themes keep the theme's colours. The choice is saved in `copilotUsageMonitor.palette` (user settings).
- **Getting started** walkthrough (**Help → Welcome**, or **Welcome: Open Walkthrough…** → "Get started with Copilot Usage Monitor (Local)"): check that your usage logs are found (names the Copilot, Claude Code and Codex folders; opens the `copilotHome` setting), pick tokens or estimated cost and a currency, set a monthly target range, and open the side bar and the panel. Its pages are four short Markdown files shipped in the `.vsix`; they hold no links or images.
- **Updates** within about half a second of a tool finishing a model call. Copilot and Codex write one usage record per completed model call, so figures move in steps, not token by token. Claude Code writes one line per streamed block of a reply; the call counts once and takes the last line's figures. Copilot's folder is scanned every 10 seconds, and as soon as it changes. The Claude Code and Codex folders are walked in full every 60 seconds, and sooner when a 10-second check of their folders' modification times sees a change (a new log, not an append to one). A Claude Code or Codex log changed in the last 5 minutes is read on every tick; one that has been quiet longer is read again only when a walk sees it change, so the next call of a session idle that long can take up to a minute to show.

How to read the numbers:

- `—` means the log did not report a value. It is never shown as `0`.
- `*` means a figure may be incomplete, for example because a log could not be read or some records lacked the field. Hover the figure for the reason.
- **session total** marks a session from Copilot before 1.0.99. Those builds write no per-call records, only one total per model when the session ends, so the whole session counts once, on the day it ended. It has no per-call, growth or tool figures. Older Copilot also logged no AI credits there, so its USD shows `—`, never `$0.00`; its tokens and calls still count.
- "AIU (as logged)" is the raw `totalNanoAiu / 1e9` value Copilot writes into its own log.
- "USD (est.)" is that AIU × $0.01, for Copilot only. GitHub prices Copilot per token, converts the price to AI credits and charges $0.01 per credit. Checked against GitHub's published per-model price table, the logged AIU matched to four decimal places. It is still an estimate: it covers only calls logged on this computer and it is not an invoice.
- Claude Code and Codex log no cost. Their calls show `—` in USD, never `$0.00`, and are not counted as missing, so a USD figure is starred only when a Copilot record lacked its credits. Where they are in scope the cost notes add "USD (est.) covers Copilot only: Claude Code and Codex log no cost; their figures are tokens." and the target line reads "(Copilot only)".

## What this is not

> Locally observed from Copilot, Claude Code and Codex session logs on this computer. Not an account statement from any of them, not your remaining allowance, and not usage from other devices or features that don't write these logs.

- **Not official.** These are local observations of an undocumented log format, not an account statement from GitHub. If you need the official figures, check your GitHub account settings.
- **Copilot: partial coverage.** Of Copilot's clients, only those that write `~/.copilot/session-state/*/events.jsonl` are counted: the Copilot CLI and the coding agent, including agent sessions started from VS Code. These Copilot uses are not counted:
  - inline completions
  - Copilot Chat in VS Code and other Chat surfaces that don't write these logs, so if you use Chat the figures are a lower bound
  - github.com, mobile, JetBrains
  - other computers
- **Claude Code and Codex: their logs on this computer only.** These are not counted:
  - other computers
  - Claude.ai and ChatGPT web usage, and other apps that don't write these logs
  - Codex archived sessions: `archived_sessions/` is listed by count in Data health, and none of its files is opened
- **Apps built on the Claude Agent SDK** write to the same `projects` folder as Claude Code, so their calls count as Claude Code.
- **Same folder name, one project.** Projects are grouped by folder name, so two different repositories cloned into folders of the same name share one row.
- **First scan.** The first scan reads your logs once; several GB of Claude Code logs take a few seconds of background reading per VS Code window.
- **Older Claude Code months may be empty.** Claude Code deletes its own transcripts after its cleanup period (30 days by default), so older Claude Code months may be empty.
- **Older Copilot is counted coarsely.** Before 1.0.99, Copilot writes one total per session when it ends. Those sessions count on their end day, show nothing while still open (or if they crashed) and have no estimated USD. Turn `sessionTotals` off to leave them out.
- **Local day.** "Today" starts at local midnight on this computer, while GitHub's own day may follow UTC.
- **Format changes.** If Copilot, Claude Code or Codex changes its log format, the status bar shows a warning icon and the panel says "Format changed" (Data health names the source). It does not quietly show smaller numbers.

## Install

The extension is not on the Marketplace yet. Build a `.vsix` and install it:

```bash
npm ci
npm run build
npm run package
code --install-extension copilot-usage-monitor-0.8.0.vsix
```

Alternatively, in VS Code use **Extensions → … → Install from VSIX…**.

## Currency

Estimated cost is always worked out in USD, from Copilot's logged AI credits. Set `copilotUsageMonitor.currency` (or run **Copilot Usage: Choose Currency…**) to show it in another currency, for example `CAD` shows `CA$17.36` instead of `$12.34`.

- **Rate:** the European Central Bank daily USD reference rate, fetched from `https://api.frankfurter.dev` (free, no key, open source) when VS Code starts, when you change the currency, and every 6 hours after that. The rate and its date are shown under the cost note in the panel and in the status bar tooltip.
- **What is sent:** one HTTPS GET with only the currency code, for example `?base=USD&symbols=CAD`. No usage figures, paths, project names or identifiers. With the default `USD` no request is ever made.
- **Targets:** `monthlyTargetMin` / `monthlyTargetMax` are read in the chosen currency.
- **Offline:** until a rate arrives, cost stays in USD with a note, and targets are not compared. A failed fetch is retried every 15 minutes.

## What it reads

Each source is read only while it is on, from its own folder, and only for logs changed within the history window (`historyMonths`, 12 months by default). The exact log shapes are in [`docs/SCHEMA.md`](docs/SCHEMA.md).

### Copilot CLI

- **Files opened:** only `<copilot folder>/session-state/<session id>/events.jsonl` for sessions written within the history window. Everything else in the folder is only listed. Lock-file names are used to tell live sessions apart. The one other file ever opened is that session's `workspace.yaml`, and only when `projectNames` is on and the project folder name is an ID (a UUID or long hex): at most 16 KB is read (a larger file is ignored), and only its `name:` line is kept. Nothing else is opened.
- **Line filtering:** each line is checked by its first bytes. Only `session.usage_record` lines are decoded and parsed, plus, when `projectNames` is on, each log's single `session.start` line (under 16 KB; larger ones are skipped), and, when `sessionTotals` is on, `session.shutdown` lines (up to 64 KB; a longer one is not decoded and is listed under Data health). Prompts, replies, tool output and file contents are skipped without being decoded.
- **Session totals:** from a `session.shutdown` line, per model, only the five token counts (`inputTokens`, `outputTokens`, `cacheReadTokens`, `cacheWriteTokens`, `reasoningTokens`), `requests.count` and `totalNanoAiu` are kept, plus the line's timestamp and `sessionStartTime`. The line (at most 64 KB) is decoded whole; the keys `filesModified`, `accountingSnapshot`, `agentMetrics`, `providerModelMetrics`, `usageAccountingWatermarks` and `currentModel` are removed during parsing and never copied, and nothing else on the line (such as `requests.cost`, `totalApiDurationMs` or `codeChanges`) is ever copied. When a session, or its session folder, also has per-call records, its session total is hidden, so nothing is counted twice; a later shutdown line replaces an earlier one instead of adding to it.
- **Project:** from `session.start` only the last folder name of `context.gitRoot`, else `context.cwd`, else the repository part of `context.repository`, is kept as the project key, and `context.repository` (if it looks like `owner/repo`) as a display label. The full path, branch, commits and everything else on that line are dropped. When that folder name is an ID (a UUID or long hex), the session title is shown instead: only the `name:` line of that session's `workspace.yaml` (under 16 KB), capped at 60 characters, with control, bidi and zero-width characters removed. Titles and `owner/repo` are display labels only: sessions are still grouped and filtered by the folder name, so two sessions in one folder stay one row (labelled with the most recently active session's title or `owner/repo`; when two disagree, the newer one shows) and a label can never merge into another project's row. Copilot writes a short title there; for a session you never renamed it can be the start of your first prompt.
- **Tool use:** the per-call `toolCounts` map (tool name → number of invocations). Tool arguments and output are never read.
- **Per-call detail (since 0.6):** `initiator` and `finishReason` are mapped to a few fixed values (`user` / `agent` / `other`; `stop` / `tool_calls` / `length` / `content_filter` / `other`), so the log's text is never kept. `toolTokenCount` and `availableToolCount` are numbers. From `copilotUsage.tokenDetails[]` only each entry's token type, token count, batch size and cost per batch are read, to split the call's AI credits by token type; the split is kept only when it adds up to the logged total, and the entry's model name is not read.
- **Fields kept:** model id, token counts, model time, AIU as logged and its split by token type, tool names with counts, tool-definition tokens and tools offered, who started the call and how it ended (fixed values), usage id, sequence, session id, timestamp, the project key and label and, for session totals, the call count and session start time.

### Claude Code

No Claude Code line is ever decoded whole. A line is first checked with a native byte search, then walked once by a depth-tracking scanner that returns the byte ranges of an allowlist of key paths, and only those ranges are decoded, through one function (`parseSlice`), each at most 4 KiB. Token counts are requested one number at a time, so the `usage` object is never decoded whole.

- **Files opened:** only regular `*.jsonl` files under `<claude folder>/projects/`: a project folder's `<session id>.jsonl` and the `*.jsonl` files below its `<session id>/` folder (subagent logs such as `subagents/agent-*.jsonl` and `subagents/workflows/*/agent-*.jsonl`), at most 6 levels below `projects/`. Only a project folder's own `.jsonl` files named like a session id, and the files below a folder named like a session id, are found; the same rule is checked again just before a file is opened. Folders are listed and files `lstat`'ed to find them; symbolic links are skipped, never followed. At most 10,000 files are looked at per scan; the rest are counted in Data health as files beyond the cap and mark the data partial. Other folders in a project folder (such as `memory/`, `tool-results/` or a plugin's folder) are not listed, and nothing outside `projects/` is listed or opened.
- **Line filtering:** a line is a candidate only if its raw bytes contain `"type":"assistant"`. The scanner tracks brackets and the current key, skips string bodies byte by byte without decoding them, and must find `type` at the top level equal to `assistant`; a key of the same name deeper in the line (inside a tool input, say) never matches. A line with `"type":"user"` in its first 256 bytes counts as activity, undecoded. Every other line is skipped undecoded. A line over 4 MiB is not read: it counts as over-long (may be usage) when its first 4 KiB show an assistant message, otherwise as over-long and not usage.
- **Fields kept:** from `message.usage` the four token counts (`input_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, `output_tokens`) and `output_tokens_details.thinking_tokens`, each requested as its own path (`service_tier` and the object's other keys are never read); `message.id` (else `requestId`) as the call's key; `message.model`; `message.stop_reason`, mapped to a fixed value; `timestamp` and `sessionId`; and the `name` of each `message.content[]` block whose `type` is `tool_use` (only those two slices of a block are looked at). With `projectNames` on, `cwd` is read from a log's usage lines until one gives a folder name: that name is kept (a worktree counts under its repository) and the path is dropped.
- **Counted once:** Claude Code writes one line per streamed block of a reply, all with the same message id. The call counts once, with the last line's figures and the tool names of all its lines. The same id in a second log (a resumed session copies its history) counts once. A line whose four token counts are all 0 (such as a `<synthetic>` placeholder) is not a call.
- **Sessions:** a session is a main log plus the subagent logs below its folder, which carry the same session id. Subagent calls count fully. A session whose logs hold only your prompts and no assistant line is not counted as a session without usage data.
- **Never read:** prompts, replies, thinking, tool inputs and results, `signature`, `gitBranch`, `version`, `uuid`, `agentId`, `isSidechain`, `message.usage.service_tier`, every line type other than `assistant`, and the files `history.jsonl`, `settings*.json`, `CLAUDE.md`, `todos/`, `file-history/`, `shell-snapshots/`, `memory/`, `tool-results/` and every file that is not a `.jsonl` log under `projects/`.

### Codex CLI

No Codex line is ever decoded whole either: the same byte search, scanner and `parseSlice` (4 KiB at most per slice) are used, and token counts are requested one number at a time, so no usage object is decoded whole.

- **Files opened:** only regular `<codex folder>/sessions/YYYY/MM/DD/rollout-*.jsonl` files changed within the history window whose name ends with a session id; a rollout file without one is skipped. Date folders must be digits and are entered only from the day before the window's first day; a year, month or day folder that cannot be listed is reported as unreadable. `archived_sessions/` is listed by name only, for a count in Data health; none of its files is opened. Nothing else in the Codex folder is listed or opened.
- **Line filtering:** a line is a candidate only if its raw bytes contain `"type":"token_usage_record"`, `"type":"turn_context"`, `"type":"session_meta"` or `"type":"event_msg"`; the scanner then confirms the top-level `type`. Every other line (prompts, replies, reasoning, tool calls) is skipped undecoded. A line over 4 MiB is not read; it is classified by its first 4 KiB only: over-long (may be usage) when they name a usage record (`token_usage_record`), otherwise over-long and not usage.
- **Fields kept:** from `token_usage_record`: `timestamp`, `payload.session_id`, `payload.response_id` (the call's key) and, from `payload.usage`, `input_tokens`, `cached_input_tokens`, `cache_write_input_tokens`, `output_tokens` and `reasoning_output_tokens`, each requested as its own path. `payload.turn_id` is read only to look up the call's model and is never kept. From `turn_context`: `payload.turn_id` and `payload.model`, so each call takes its turn's model, else the latest model seen in the log (at most 1,024 turns are remembered per log, in memory, while the log is read). Every call is tied to its log by the session id at the end of the file name. A record whose five counts are all 0 is not a call. With `projectNames` on, from the first `session_meta`: `payload.cwd`, reduced to its folder name and dropped.
- **Session totals:** with `sessionTotals` on, a log that has no `token_usage_record` (older Codex) counts once, as a "session total", from the same five counts of `payload.info.total_token_usage` on its last `event_msg` of type `token_count`, with the latest model seen in the log. The first time the log yields a per-call record its session total is deleted, so a total never outlives the calls of its own log; after that its `event_msg` lines are no longer scanned.
- **Never read:** `rate_limits`, `last_token_usage`, `model_context_window`, `turn_token_usage`, `thread_token_usage`, `instructions`, `git`, sandbox and permission fields, `cli_version`, `originator`, `total_tokens`, every `response_item` line, and the files `auth.json`, `config.toml`, `history.jsonl`, `log/`, sqlite files and `archived_sessions/`.

### One token convention

Input tokens include cached tokens for every source, so uncached input is input − cache read − cache write. Copilot logs input that way. Claude Code logs uncached input alone, so its input is `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`, plain arithmetic on the kept counts. Codex's `input_tokens` already include cache reads and are copied as logged; its cache writes (`cache_write_input_tokens`) are kept apart, because whether Codex counts them in `input_tokens` is unverified. Reasoning and thinking tokens are part of output for every source.

### Everything the extension does with them

- **Memory only:** everything kept stays in memory. Nothing is written to disk and no usage data is sent anywhere.
- **Output channel:** the "Copilot Usage Monitor" output channel gets counts, error codes and timings only, never log content or paths.
- **Panel:** the details panel runs no scripts and loads no remote resources. Its only links are VS Code command links, and the panel allows exactly seven commands: show a month, show a section, set the unit, set a filter, list a session's calls, collapse or expand the section navigation, and choose the colours. The selected section and session are kept in memory only.
- **Side bar:** a web view with the same rules as the panel: no scripts, no local or remote resources, the same content security policy, and only five command links (open the panel, show a section, set the project filter, switch the unit, choose the currency). The source rows use the same filter command. It shows figures the extension already holds and opens no other file; every name from the logs is escaped. Open workspace folder names are used only to pick the "This workspace" project and are never stored.
- **No credentials, no network:** unlike tools that read your sign-in tokens, this extension never reads credentials (Copilot's, Claude Code's or Codex's). It works only from the log files above. Its one network request is the optional exchange rate described under [Currency](#currency); with the default USD it never uses the network.
- **Settings:** the extension writes five settings and nothing else: the unit switch saves `copilotUsageMonitor.display` (at the scope where it is set; user settings when it is set nowhere), **Choose Currency…** saves `copilotUsageMonitor.currency`, **Choose Colours…** saves `copilotUsageMonitor.palette` and the panel's navigation toggle saves `copilotUsageMonitor.panelNavCollapsed`, all in your VS Code user settings, and the target alert's **Don't show again** sets `copilotUsageMonitor.targetAlert` to `false`.
- **Notifications:** none, unless you turn on `copilotUsageMonitor.targetAlert`; then at most one per calendar month per window, as described under the target range. Which month was already announced is kept in memory only.

Automated tests enforce these rules. They scan the source and the bundle for network, persistence and telemetry APIs, allowing exactly one `fetch`, in `src/vscode/exchangeRate.ts`, pinned to the exchange-rate URL. They allow a notification only in the target alert's file and a settings write only for those five keys. They also check the exact files inside the `.vsix` (the bundle, `package.json`, `README.md`, `LICENSE`, the three logo files under `media/` and the walkthrough's four Markdown files). For every source, synthetic logs put a canary string into each content field (prompts, replies, thinking, tool inputs, paths, Codex `instructions` and `rate_limits`), and the tests check it never reaches a record, the UI or the output channel. File-system spy tests check that a source that is off is never touched, and that only paths of each source's log pattern are opened. Scanner gates check that `JSON.parse` runs in the Claude Code and Codex readers only through `parseSlice`, that a slice over 4 KiB is refused, and that `"type":"assistant"` or a `usage` object hidden inside a tool input or a string never makes or changes a record.

## Development

```bash
npm ci
npm test                    # unit tests (Vitest)
npm run typecheck
npm run test:integration    # extension-host tests (downloads VS Code 1.90 for testing only)
npm run test:perf           # perf budgets (sets PERF=1 and --expose-gc itself)
npm run package
```

`npm run probe` prints a shape-only summary of your Copilot logs: key paths, types and counts, never values. Use it to check `docs/SCHEMA.md` against a new Copilot version before relying on the numbers. `npm run probe:claude` and `npm run probe:codex` do the same for Claude Code's `projects` folder (`CLAUDE_CONFIG_DIR`, else `~/.claude`) and the Codex CLI's `sessions` folder (`CODEX_HOME`, else `~/.codex`); they print no value, no file name and no project or session folder name (a fixed list of known structural folder names, such as `subagents` or `memory`, is printed). Key names that look like identifiers and line or block type values made of lowercase words may be printed, as shape; any other key is masked. `npm run probe:chat` does the same for VS Code Copilot Chat's own logs. Those logs are not read by the extension yet; see `docs/plans` §13.

When reporting a problem, include the probe output if it helps. It contains no prompts, code or paths.
