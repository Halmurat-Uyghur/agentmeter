# v0.4 design: section navigation, side bar summary, session totals

Date: 2026-11-06. Owner request: learn from CodeBurn, but read local files only, with no authentication. Owner liked CodeBurn's side tab navigation. Owner chose: older sessions count as one total per session.

Ten design notes back this spec, in `docs/design/v0.4-notes/` (F1–F5, O1–O5). Where they disagree, this spec decides; for anything this spec does not mention, follow the note named in each section.

## Why

- The owner's work sessions (cibc-*, qa, vcaps…) were written by Copilot builds older than 1.0.99. They have no per-call `session.usage_record` lines, so v0.3 shows "—" for them. Each one still wrote a `session.shutdown` line with per-model totals. On this machine 29 of 39 logs are shutdown-only.
- CodeBurn's dashboard has a left-hand section menu that the owner liked. Our panel is one long page.
- CodeBurn reads Copilot and Claude sign-in tokens and calls private usage APIs. We stay the opposite: local files only, no network, no credentials, nothing stored. That promise is the product.

## Goals

1. Count sessions that have only a `session.shutdown` line, labelled "session total".
2. A left-hand section menu in the details panel, with scripts still off.
3. A native side bar view (activity bar) with a short summary.
4. Keep every existing privacy and safety gate; extend them to the new code.

## Non-goals (v0.4)

Per-session "why it cost" detail, the `initiator` field, a price table, what-if pricing, exports, an LM tool or MCP server, pace or projection, quota or "remaining" figures, reading VS Code Chat files or `session-store.db`, pop-ups.

## Anti-goals (would make this a failure even if it works)

- Any network call, credential read or persisted state.
- A path, prompt, title or `aiCreditsStatus` string surviving the parse of a shutdown line.
- Legacy sessions showing "$0.00": they logged no cost, so they show "—" for USD.
- Counting a session twice (per-call records plus its shutdown total).

## Decisions

### D28: prototype-key hardening (do first; F4 Finding 0)

`MODEL_ID` and `TOOL_NAME` reject `__proto__`, `constructor` and `prototype`. Every object keyed by log data (`byModel`, `tools`, and the new shutdown model map) is created with `Object.create(null)` or is a `Map`. Add a regression test with a `"model":"__proto__"` line: no exception, and `Object.prototype` stays clean.

### D29: session totals from `session.shutdown` (overrides D3; detail in F1)

- **Gate:** new line class `shutdown` for lines starting `{"type":"session.shutdown"`. Lines over `MAX_SHUTDOWN_BYTES` (64 KiB) are not decoded and count toward a new `health.shutdownOversize`, which feeds `partial`. A reordered or re-spaced shutdown line is `suspect`, the same as a usage line.
- **Parse:** `parseShutdownLine(line, folderId)` decodes with a reviver that drops `filesModified`, `accountingSnapshot`, `agentMetrics`, `providerModelMetrics`, `usageAccountingWatermarks` and `currentModel`, then copies an allowlist into fresh objects. Per model it keeps the five `usage.*Tokens` ints, `requests.count` and `totalNanoAiu`. It also keeps the line `timestamp` and the top-level int `sessionStartTime`. It never reads `requests.cost` or `totalPremiumRequests`.
- **Records:** each model becomes a `UsageRecord` with `kind: "sessionTotal"`, key `shutdown:<folderId>:<model>`, no `tools`, `calls = requests.count`, dated at the shutdown `timestamp`.
- **Zero cost:** `totalNanoAiu === 0` with non-zero tokens is treated as not reported (`undefined`).
- **Dedupe:** the store hides a session-total record while any per-call record exists for the same `sessionId`. `setSessionTotals(folderId, records)` replaces that folder's earlier totals, so the last shutdown wins and totals are never summed. File reset and window drop also remove them.
- **Counts:** `Counts` gains `sessionTotals: number` (session-total records aggregated) and `calls: number`. `calls` is per-call records plus `requests.count` of session totals. "Calls" cells use `calls`; per-call figures (per call, growth) use only per-call records.
- **Health:** add `sessionsFromTotals` and `shutdownOversize`. A log whose only shutdown has empty `modelMetrics` counts as without usage, not as format-changed.
- **Setting:** `copilotUsageMonitor.sessionTotals` (boolean, default `true`, machine scope). Off means shutdown lines are skipped without decoding (the v0.3 read surface).
- **Filters:** the project filter applies to session totals. The tool filter excludes them, because they have no tool data.

### D30: section navigation (detail in F2 and O3)

- **Sections, in order:** `overview` Overview, `daily` Daily, `sessions` Sessions, `models` Models, `projects` Projects, `tools` Tools, `insights` Insights, then a separator and `health` Data health.
- **State:** the selected section lives in the extension host (`DetailsPanel`). It is not persisted and not part of `ViewOptions`. On every render the panel shows the selected section only.
- **Command:** new command `copilotUsageMonitor.showSection(id?)`. An id from the closed list switches section and opens the panel. No argument opens a quick pick. Anything else is ignored. `PANEL_COMMANDS` grows from 3 to 4, and a test pins the exact list. Fragment anchors are rejected, because every redraw reloads the page.
- **Layout:** a shared header on every section (title, month picker, Tokens/USD switch, filter chips, state banner), then `<nav aria-label="Sections">` and `<main aria-labelledby>`. The active link has `aria-current="page"`. Below 720 px the nav becomes a wrapping row above the content. Use theme variables only, add focus outlines, and add high-contrast borders.
- **Refactor:** split `panelHtml.ts` into `src/core/panel/*.ts`, one file per section plus shared chrome. `panelHtml.ts` stays as the façade that the tests import. `renderPanelHtml(s, csp, view, section = "overview")`.
- **Redraws:** `DetailsPanel.render()` skips assigning `webview.html` when the HTML string is unchanged.

### D31: side bar view (detail in F3)

- **View:** a native `TreeView`, not a webview. Activity-bar container `copilotUsageMonitor` with the icon `$(graph)` (a codicon, so no new media file). One view, `copilotUsageMonitor.summary`, titled "Summary".
- **Model:** a pure `buildSidebarModel(snapshot, view)` in `src/core/sidebarModel.ts`, with no `vscode` import, so it can be unit-tested. A thin adapter in `src/vscode/sidebar.ts`.
- **Rows:** Today, Last 7 days, This month (target-range icon), Current session, Top projects (5), Top models (5, collapsed), and Data health (only when there is something to report).
  - Clicking a row opens the panel at the matching section; a project row also toggles the project filter.
  - Values follow the same rules as the panel: `—` never `0`, `*` for partial, and "session total" in descriptions and tooltips.
- **States:** `viewsWelcome` covers loading, no folder and no permission, driven by a `copilotUsageMonitor.state` context key.
- **Title actions:** Open panel, Switch unit and Refresh.
- **Updates:** fire `onDidChangeTreeData` only while the view is visible (250 ms trailing debounce). When hidden, mark it stale and fire once when it becomes visible.
- **Unfiltered totals:** `Snapshot` gains `thisMonth?: Totals` and `last7?: Totals`, both ignoring the filter. The status bar reads `thisMonth`, which fixes the existing bug where the USD status bar showed a filtered month.

### D32: section content (detail in O4, O1, O2, O3)

- **Overview:** tiles for Today, Current session, Last 7 days (with the change against the prior 7 days, as ▲/▼ and a multiplier or "N in 10"; no `%` because of the copy gate) and Month (with the target state). Then the monthly trend.
- **Daily:** the daily trend and the calendar. Session totals are counted in the day they ended, with a footnote.
- **Sessions:** current session tiles. Then costliest sessions of the viewed month: the snapshot keeps up to 50, the table shows 10 and folds the rest. Columns: project or title, started, calls, top model, tokens, USD (est.), cache-read share, growth ▲, and a "session total" tag on backfilled rows.
- **Models:** the viewed month's model table, plus a Share column.
- **Projects and Tools:** the existing tables. Tools gets a footnote that session totals have no tool data.
- **Insights:** I2 (sessions that grew costly, with a $0.50 floor) and I3 (low cache reuse per model), from O2, using O2's wording rules. Session totals are excluded and a footer says so. I1 and I4 are deferred.
- **Data health:** the existing facts, plus "Sessions counted from session totals" and shutdown oversize.

### D33: status bar

Text and colour are unchanged. The tooltip stays untrusted. Add `accessibilityInformation`. The month figure comes from `thisMonth` (D31).

## Copy rules

Existing rules apply: none of the banned words (bill, quota, limit, remaining…), no `%`, `—` for unknown, `*` for partial. The "session total" hover text is the exact string from O3.

## Build order (each step leaves `npm test` and `npm run typecheck` green)

1. D28 hardening.
2. D29 data layer: extract, tailer, types, store, monitor, setting, health, and the minimum format and panel footnotes. Tests come from F1 §9 and F5.
3. D30 panel split and navigation, plus D32 section content.
4. D31 side bar, `thisMonth`/`last7`, D33, package.json contributions, and integration tests.
5. Docs: README, CHANGELOG 0.4.0, SCHEMA, plan §16 with D28–D33, version 0.4.0, `.vsix` packaging check.

## Verification

`npm run typecheck`, `npm test`, `npm run build`, `PERF=1` perf test, integration tests (`npm run test:integration` or the F5 local config), `npm run package`. Check the `.vsix` file list.

## Addendum A (2026-11-06): CodeBurn-style look

After testing v0.4 in VS Code, the owner asked for CodeBurn's look and feel for both the side bar and the dashboard. Reference: CodeBurn 1.0.2's Summary view and dashboard, as observed in the owner's own VS Code. CodeBurn's features stay out unless listed here. Owner decision: **no "Projected month" card** (D23 stands: no projection or pace).

### A1: side bar becomes a no-script webview view (replaces the D31 TreeView)
- **View:** `registerWebviewViewProvider` for `copilotUsageMonitor.summary`, with scripts off, `localResourceRoots: []`, the same CSP as the panel, and command links only from a closed list (`showDetails`, `showSection`, `setFilter`, `toggleUnit`). The pure model stays testable: `buildSidebarModel` gives the data and `renderSidebarHtml` gives the HTML.
- **Layout:** small grey group headings, then label and value rows with right-aligned values. No row icons. Compact, using theme variables.
  - **This workspace · <name>**: Today and Last 7 days for the project matching the open workspace folder (folder basename or `owner/repo` label). Hidden when nothing matches.
  - **All projects**: Today, Last 7 days, This month (target state shown as a small marker).
  - **Top projects, last 7 days**: 5 rows. A click filters and opens Projects.
  - **Top models, last 7 days**: 5 rows. A click opens Models.
  - **Insights**: "N findings · Review", linking to Insights. Shown only when N > 0.
  - **Data health note**: only when partial or format-changed.
  - **Open dashboard** button.
- **No plan or allowance meters.** CodeBurn reads sign-in tokens for those; we never do.
- **Updates:** redraw only while visible, skip an unchanged HTML string, keep the 250 ms debounce. The welcome states (loading, no folder, no permission) become in-page states.

### A2: dashboard look
- **Header:** product name styled as a wordmark, plus the existing "Local" chip.
- **Left menu:** an inline SVG icon on each item. Group labels: **Usage** (Sessions, Daily, Models, Projects, Tools), **Insight** (Insights), **Health** (Data health). Overview sits on top with no group.
- **Overview layout:**
  - **Today hero card:** a large figure, calls and sessions. A sub-row shows Yesterday, 7-day average (per active day) and the change against yesterday as ▲/▼ with a multiplier or "N in 10" (no "%"), with "—" when there is no data.
  - **Activity heatmap:** weekday rows × weeks columns, from the days in the history window.
  - **Cache-reuse ring:** cache-read share of prompt tokens for the viewed month, as "N in 100", drawn in SVG.
  - **Month to date card:** the total, a small cumulative SVG line, and the change against last month at the same day ("vs October at this point"). No projection.
  - **Daily spend (or tokens) bar chart:** last 30 days, a dashed average line, today's bar in the accent colour, and Avg/day, Peak and Yesterday chips.
- **Accent colour:** `--vscode-charts-orange`, falling back to `--vscode-charts-yellow`. Everything else uses theme variables.
- All existing copy rules still apply.
